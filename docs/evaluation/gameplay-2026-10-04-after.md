## 0. 结论

**判定：修好 1 个小 bug 后可以发布（ship after fixing X）。**

**X = 聚变光矛的「分裂」动词让武器变弱**（§2.3，S 级，约半小时）。它是一张"陷阱卡"：玩家选了反而掉伤害。而进化后的激光恰好是最常见的 build 之一。

另外强烈建议在同一次提交里顺手修掉两件 S 级小事：
- 窗口尺寸变化会清空 HUD 全部 toast（§5.4）；
- 竖直摇杆的轻微横向漂移会翻转朝向（§5.5）。

这两件不改也不阻塞发布。

**整体判断：**
- 13 条建议全部落地，而且大多数做到了原意：
  - S1：Boss 现在打满目标时长；
  - S3：塌缩区成了一个真实的选择；
  - S6–S9：死亡节拍、前摇、手机 HUD、音乐/提示都修好了；
  - S12：协议、分数、商店数值都能用，旧存档兼容。
- 测试全绿：tsc 0、eslint 0、vitest 476/476；Playwright default 82、mobile 9、iphone 6、portrait 7、perf 4，全部通过。
- 15 次浏览器会话里没有一条 console 错误。

**没有达到原意的地方：**
- S2 动词卡：大半在第 1 层就饱和，+% 卡占比只从 30% 降到 21%；提交里写的"18 张动词卡先于第一张 +% 卡"不成立。
- S5 领航员：风筝两分钟仍然只杀 1.3 个。
- S11 新的开局无人机：让炮长和领航员"站着不动"的死亡时间从 43 s / 50 s 缩到 14 s / 15 s。

这些都是平衡或设计问题，不是 bug，可以在发布后用遥测验证。

## 1. S1 Boss（8 种子 × 8 关；不死，autopilot 瞄准）

方法同原评估 §10：装好 build → `setLevel` → `setTime(at−20)` → 步进到 `bossSpawned`。计时从刷出算起（含走进来的时间），260 s 上限算未杀。"前"是在 `a247635` 快照上用同一脚本测的，所以和原评估表的数字略有出入（引擎在那之前已经变过），但前后两列可以直接比。

### 1.3 真人 10–16 级打 5:00 Boss（估计）

我按"12 级真人"配了一个 build：刀 6、激光 3、磁轨 2、核心 2、冷却 1；"16 级"为刀 8、激光 4、磁轨 3、核心 3、冷却 2、放大 1。

TTK 中位（s），格式为 前 → 后：

| 关 | L12 | L16 |
|---|---|---|
| station 母舰 | 17.0 → **31.5** | 10.2 → 29.8 |
| cargo | 33.5 → 34.9 | 9.2 → 25.7 |
| lab 母巢 | 151 → 171（2/8 未杀） | 78 → 99 |
| orbit | 16.2 → 28.3 | 12.5 → 28.4 |
| reactor | 47.8 → 47.8 | 16.4 → 30.8 |
| derelict 打捞巨臂 | 96 → 105 | 28 → 28 |
| foundry | 59 → 89 | 20 → 28 |
| singularity | 27 → 32 | 17 → 29 |

**读法：**
- 12–16 级的真人，5:00 Boss 现在普遍是一场 25–35 s 的战斗：母舰 6 s 一次冲锋，能出现 4–5 次。这正是 S1 想要的，而不是"太长"。
- lab 母巢和 derelict 打捞巨臂对这个 build 本来就要 1.5–3 分钟，S1 几乎没碰它们：慢于目标的 build 不被抬血。
- 母巢 171 s / 2 未杀是早就存在的问题，不属于 S1。
- 风险在于，bot 的死亡中位从 317 s 变成 326 s，死亡集中在 5:10–5:40；station 上 7/16 死于母舰（原评估是 bolt 8/13）。bot 在这里不躲冲锋，真人会躲。建议发布后在遥测里看 `run_end.killedBy = mothership` 的比例。

### 1.4 血条行为与边界

血条"倒涨"指的是比例回升超过 10%。统计以 64 场为单位：

| build | 血量被抬过的场次 | 比例回升 ≥10% | ≥20% | ≥30% | 触到 60× 上限 |
|---|---|---|---|---|---|
| human 5:00 | 40/64 | 9 | 1 | 0 | 1 |
| human 10:00 | 59/64 | 0 | 0 | 0 | 0 |
| human 终局 | 64/64 | 1 | 0 | 0 | 3 |
| L16 5:00 | 44/64 | 17 | 5 | 1 | 0 |
| L12 5:00 | 27/64 | 4 | 2 | 1 | 0 |
| 夸张 build（L90 全进化打 5:00） | – | – | 最大 0.48 | – | 每关 2–5/8 |

- 绝大多数抬血保持了比例，玩家看不见。
- "回到 50%"的情况真实存在，但只在第一个窗口就打掉过半血量时发生：L16 打 5:00 有 5/64 场回升 ≥20%，最大一次从约 10% 跳回 50%。看上去像 Boss 回血，没有任何提示。`bossScaled` 事件只在模拟侧，视图不消费。
- 60× 上限只在极端过强的 build 上触到：L90 打 5:00 时 8 关里 5 关有 5/8 场。现实 build 里，human 5:00 为 1/64，终局为 3/64。到了上限，这场就比目标短。
- 打捞巨臂这类护盾弧仍然是唯一让"站着不动"打不动的机制：human 5:00 站定 182–260 s。这一点和原评估的观察一致。

**战斗中开箱**（station / derelict / singularity × 4 种子，在首次命中后第 2 s 或第 6 s 强制开一个 Boss 箱）：

| 开箱时间 | 效果 |
|---|---|
| 2 s，第一次结算之前 | TTK 与不开箱基本相同（station 10:00：41 vs 41；终局 72 vs 71）。跨窗口被丢弃，符合描述。 |
| 6 s，结算之后 | 检查被关闭，TTK 大幅缩短：station 10:00 从 41 降到 13–21 s，终局从 72 降到 13–48 s。 |

两种都符合提交描述（"奖励应在战斗里感受到"）。不过这意味着：**第一次结算之后的任何补给箱都会永久结束检查**。自然对局里这种情况不常见：human 10:00 有箱/无箱的 TTK 为 41.7 / 41.8 s。

可以被利用的地方（设计观察）：检查从首次命中起只持续目标时长的一半（5:00 为 12.5 s），而且只会往上抬。所以"先轻打一下，躲 12.5 s，再全力输出"能绕过它。普通玩家不会这么做，速通玩家会。

浏览器侧的血条观察见 §5.1。

### 2.2 出卡逻辑

- **验证通过**：满 build 下 8 种子 × 2 策略 × 40 次升级，没有一次违规（未满 3 层的武器不出 +%，动词卡只 +1，不超过 3 层）。
